# 병원 리뷰 관리

리뷰는 **사람이 넣고**, 분류·초안·검사·보고는 이 스킬이 하고, **게시는 사람이** 한다.
병원 답글은 일반 가게 답글과 다르다. 한 줄만 잘못 써도 환자 정보 누설(의료법 제19조), 환자 유인(제27조 제3항), 불법 의료광고(제56조)가 된다. 그래서 답글마다 검사기를 통과시킨다.

## 시작 전: 병원 폴더 확인

- 병원 폴더 맨 위 `review_watch.json` (없으면 [assets/review_watch.example.json](assets/review_watch.example.json)을 복사).
- 리뷰 파일: `data/reviews/*.csv` (열 형식은 [assets/reviews_template.csv](assets/reviews_template.csv)). 리뷰 원문과 닉네임은 개인정보라 git에 올리지 않는다(`.gitignore`에 `projects/*/data/reviews/`, `projects/*/output/reviews/`).

## 작업 순서

### 1. 리뷰 받기
- 사용자가 붙여 넣은 리뷰(관리자 화면 복사, 캡처, 내보내기 파일)를 `data/reviews/<날짜>_<채널>.csv`로 정리한다. 열: `platform,date,rating,author,text,reply,reply_draft`.
- 캡처 이미지면 글자를 그대로 옮긴다. 고치거나 요약하지 않는다.
- 리뷰 사이트를 자동으로 긁지 않는다(네이버·강남언니 리뷰는 로그인·봇 차단 영역). 플랫폼이 공식 내보내기나 API를 열어 주면 그것만 쓴다.

### 2. 분류와 보고서
```bash
python3 $SKILL/scripts/review_care.py run review_watch.json
```
- 분류: **긴급**(부작용·물집·염증·환불·소송·신고·보건소) → **불만** → **질문** → **칭찬** → 기타.
- 표시(⚑): 리뷰에 연락처 노출, 짧은 저평점(허위 의심), 다른 병원 유도.
- 보고서 `output/reviews/<날짜>_review-report.html`: 요약, 오늘 할 일(긴급 미답변), 채널별 분류, 월별 별점, 불만에 자주 나온 말, 리뷰별 답글·검사 결과.
- **긴급 리뷰는 답글보다 먼저 사용자에게 알린다**: "원장님이 오늘 확인하고 개별 연락하세요." 공개 답글은 짧은 사과 + 개별 연락 안내만.

### 3. 답글 초안 쓰기
미답변 리뷰마다 `reply_draft` 열에 초안을 쓴다. [references/reply-guide.md](references/reply-guide.md)의 분류별 틀을 따른다. 원칙:
- **리뷰에 적힌 것 밖의 진료 정보를 쓰지 않는다.** 시술명·날짜·기록·진단·담당자 이름을 꺼내지 않는다. 리뷰어가 시술명을 썼어도 답글에서 되풀이하지 않는다("말씀 주신 불편", "남겨 주신 이야기").
- **공개 답글에서 보상·할인·환불·무료 재시술을 약속하지 않는다.** 개별 연락으로 옮긴다.
- **답글을 광고로 쓰지 않는다.** 효과·최고·이벤트·예약 유도 금지. 칭찬 답글은 감사 + 앞으로의 다짐만.
- **반박·위협하지 않는다.** "사실이 아닙니다", "법적 조치"는 공개 답글에 쓰지 않는다.
- 3~5문장, 존댓말, 병원 이름 대신 "저희 병원". 병원 실명 비공개 규칙이 있는 병원은 그 규칙을 따른다.

### 4. 검사
```bash
python3 $SKILL/scripts/review_care.py run review_watch.json      # 전체 (초안 block 있으면 종료 코드 1)
python3 $SKILL/scripts/review_care.py check "답글 문장" --cat complaint   # 한 개
```
- block이 있으면 고쳐서 다시 돌린다. block이 남은 초안은 사용자에게 "게시용"으로 넘기지 않는다.
- 검사 결과에 근거 조문 원문이 함께 나온다(medical-ad-blog 스킬의 `references/law/`를 읽음).

### 5. 사용자에게 넘기기
- 보고서 경로, 긴급 건, 게시할 초안 목록(복사해 쓰기 쉽게)을 준다.
- 사용자가 게시하면 그 답글을 `reply` 열로 옮긴다(다음 보고서에서 '답변 완료').

## 허위·악성 리뷰

- 먼저 **실제 내원 여부**를 병원이 확인한다(이 스킬은 진료 기록을 보지 않는다).
- 내원 기록이 없고 사실과 다른 내용이면: 공개 반박 대신 플랫폼에 **삭제·임시조치 요청**(정보통신망법 제44조의2, 임시조치는 30일 이내). 요청서에는 어떤 내용이 왜 사실과 다른지 소명한다. 환자 정보는 요청서에도 쓰지 않는다.
- 실제 환자의 불만이면 허위가 아니다. 삭제 요청 대상이 아니고 응대 대상이다.
- 자세한 절차와 조문: [references/rules.md](references/rules.md)

## 절대 하지 않는 일

- 리뷰 작성 대가(할인·적립·사은품)를 걸지 않는다 → 환자 유인(의료법 제27조 제3항, 3년 이하 징역).
- 직원·지인에게 리뷰를 쓰게 하거나 가짜 리뷰를 만들지 않는다 → 거짓 광고(제56조 제2항 제3호)·표시광고법.
- 받은 리뷰를 블로그·SNS·광고·홈페이지에 옮겨 싣지 않는다 → 치료경험담 광고(제56조 제2항 제2호).
- 답글을 자동으로 게시하지 않는다. 사람이 읽고 올린다.

## 규칙 고치기

검사기가 놓치거나 잘못 잡은 답글을 찾으면 `scripts/review_care.py`의 `REPLY_RULES`·`CATS`를 고치고, `selftest()` 사례에 그 문장을 넣은 뒤 `python3 $SKILL/scripts/review_care.py selftest`가 전부 맞아야 한다.
