# 시술가 조사 (강남언니 공개 이벤트)

주변 병원이 강남언니에 올린 **이벤트 가격**을 모아, 우리 병원 가격을 정하거나 원장님께 보고할 때 쓰는 내부 자료를 만든다.

## 언제 쓰나

| 상황 | 하는 일 |
|---|---|
| 원장님 월간 보고 | `run`으로 새로 조사 → 보고서 첫 표(한눈에 보기)와 지난 조사 대비 변동을 요약 |
| 새 시술 가격 정하기 | 해당 시술 카드의 "용량별 가격"과 "단위당 중앙값"을 보고 가격대 제안 |
| "서면 울쎄라 얼마야?" 같은 질문 | 오늘 조사본이 있으면 `summary.json`으로 바로 답, 없으면 그 시술만 넣은 설정으로 조사 |
| 블로그 주제 고르기 | 리뷰가 많이 쌓인 이벤트 = 찾는 사람이 많은 시술 → 주제 후보로 제안 (가격은 글에 쓰지 않음) |
| 새 병원 영업(Dr.GEO) | 그 병원 지역으로 설정을 만들어 조사 → 지역 가격 지도 |

## 실행

병원 폴더마다 `price_watch.json`이 하나 있다. 없으면 [references/config.md](references/config.md)를 보고 만든다.

```bash
cd projects/<병원폴더>
python3 ../../shared/skills/clinic-price-research/scripts/price_research.py run price_watch.json
```

- 목록 약 70장 + 상세 약 100장을 4~7초 간격으로 연다. **10~15분** 걸리므로 백그라운드로 돌린다.
- 같은 날 다시 돌리면 저장본을 재사용한다(새 요청 0회). 보고서만 다시 만들 땐 `report`.
- 결과: `data/prices/<날짜>/snapshot.json`(원자료), `summary.json`(요약), `output/prices/<날짜>_price-report.html`(보고서).
- 파서를 고쳤으면 `python3 scripts/price_research.py selftest`가 통과해야 한다.

## 결과를 사용자에게 전할 때

1. 보고서 HTML을 SendUserFile로 보낸다.
2. 대화에는 3~5줄만: 눈에 띄는 가격대, 지난 조사 대비 큰 변동, 표본이 적은 시술.
3. 수치를 말할 땐 **"강남언니 앱 결제 이벤트가 기준"**임을 붙인다. 정가·상담가가 아니다.
4. 표본이 병원 3곳 미만인 시술은 "참고 수준"이라고 말한다.

## 지켜야 할 것 (자세한 이유: [references/rules.md](references/rules.md))

- **사람이 요청할 때만** 돌린다. cron·스케줄 작업에 걸지 않는다. 강남언니 robots.txt는 검색엔진 외 자동 수집을 허용하지 않으므로, 대량·정기 수집은 하지 않는다.
- 로그인, 후기 본문, 쿠폰, 예약·상담 신청은 건드리지 않는다. 차단·보안 확인 화면이 나오면 우회하지 않고 멈춘 뒤 사용자에게 알린다.
- 조사 결과를 **블로그·광고·SNS 원고에 넣지 않는다.** 타 병원 가격 비교는 의료광고 금지 사항이다(BRAND.md, 의료법 제56조).
- 할인·이벤트 가격을 광고에 쓰는 것도 별도 규정이 있다. 우리 병원 가격을 광고할 땐 medical-ad-blog 검사기를 거친다.

## 한계

- 표본: 검색어 × 정렬 몇 가지 × 첫 장(20건)만 본다. 강남언니에 이벤트가 없는 병원은 빠진다.
- 단품/패키지·용량 분류는 옵션명 글자로 자동 판단한다. 의사결정 전에는 보고서의 원문 링크로 확인한다.
- 강남언니 화면 구조가 바뀌면 파서가 깨진다. 조사 결과가 0건이거나 selftest가 실패하면 `tests/`의 저장본과 새 화면을 비교해 고친다.
