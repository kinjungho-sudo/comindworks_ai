# 의료광고 규정 준수 + GEO 병원 블로그

병원 블로그는 두 가지를 동시에 만족해야 한다. 하나는 **의료광고 규정**(어기면 업무정지·벌금, 의료법 제56조·제89조)이고, 다른 하나는 **AI 검색에 인용되는 글**(근거·구조·신뢰 신호)이다. 둘이 부딪치면 언제나 규정이 이긴다. 효과 수치·후기·우열 비교는 GEO에 도움이 될 것처럼 보여도 넣지 않는다.

이 스킬이 만드는 글이 국내 병원 마케팅 글과 다른 점은 벤치마크에서 나왔다. 국내 병원 글 15건 중 9건이 부작용을 빠뜨렸고, 의료진 감수 표기는 23건 중 0건이었다. 그래서 이 스킬은 **부작용을 독립 섹션으로, 감수·작성일·참고 문헌을 빠짐없이** 넣는 것을 차별점으로 삼는다.

## 시작 전: 병원 폴더 확인

작업은 병원(지점)마다 하나인 폴더에서 한다. 폴더에 아래가 있는지 먼저 본다. 없으면 [references/project-setup.md](references/project-setup.md)를 읽고 만든다.

| 파일 | 용도 |
|---|---|
| `BRAND.md` | 독자, 미션, 금지 표현(`### Taboo phrases` → 검사기가 block) |
| `VOICE.md` | 말투(예: 다정한 존댓말, 병원은 "저희 병원") |
| `medad_local.json` | 병원별 추가 규칙. 실명 비공개라면 실명·지점명 패턴을 block으로 |
| `docs/decisions.md` | 결정 기록 (감수 표기, 진료과목 명칭, 사전심의 여부 등) |

검사기와 시뮬레이션 지침은 이 스킬 폴더에 있다. 아래에서 `$SKILL`은 이 SKILL.md가 있는 폴더다.

## 작업 순서

### 1. 주제와 범위 정하기
- 검색 의도가 분명한 질문형 주제를 고른다. 예: "기미와 잡티 구분", "초음파 vs 고주파 리프팅".
- 병원이 실제로 하지 않는 시술을 "저희가 하는 것"처럼 쓰지 않는다. 모르면 `[원장님 확인: 시행 여부]`로 남긴다.
- 신의료기술 평가를 받지 않은 시술은 광고할 수 없다(제1호). 생소한 시술이면 사용자에게 확인한다.

### 2. 근거 모으기
- 학회 지침, 체계적 문헌고찰, 공공기관(질병관리청, AAD, NHS 등) 자료를 우선한다. 출처는 3~10건이 적당하다.
- 본문에 쓸 문장마다 **원문(초록·본문)에 그 내용이 실제로 있는지** 확인한다. 이전 작업에서 검수 에이전트가 찾은 문제의 대부분은 표현이 아니라 "인용한 문헌이 그 주장을 받치지 않음"이었다.
- 제조사 후원 연구, 소규모 사례 연구는 한계를 함께 적거나 다른 출처로 바꾼다.

### 3. 원고 쓰기
[references/standard.md](references/standard.md)의 구조와 문장 규칙을 따른다. 틀은 [assets/post-template.md](assets/post-template.md)를 복사해서 쓴다. 꼭 지킬 것:
- 첫 문장은 정의문("○○는 …예요"). 질문형 소제목 5~8개, 각 섹션 첫 문장이 직답.
- **부작용·반응 섹션을 따로 두고, 첫 줄에 개인차 문구**(본문 크기, 굵게).
- 수치는 유병률·부작용 빈도·크기 같은 비효능 수치만 쓰고, 바로 옆에 출처 번호를 단다.
- 병원이 정할 사실(시행 시술, 장비, 횟수, 회복 기간, 주의 대상, 진료 시간)은 지어내지 말고 `[원장님 확인: …]`로 남긴다.
- 실명 비공개 병원이면 "저희 병원"으로만 쓴다. 작성자·태그에 "○○피부과" 같은 명칭을 쓰지 않는다(제9호).
- 전문의약품 이름, 장비 상품명은 쓰지 않는다. "바르는 약", "피코초 레이저"처럼 종류로 쓴다.

### 4. 의료광고 자동 검사
```bash
python3 $SKILL/scripts/medad_check.py output/<폴더>/<원고>.md --project .
```
- **block이 1건이라도 있으면** 고친 뒤 다시 돌린다. block이 남은 원고는 사용자에게 보여주지 않는다.
- **warn**은 해당 줄을 읽고 판단한다. 보고할 때 warn 목록과 판단 이유를 적는다.
- 출력 끝의 **수동 확인 항목**은 자동으로 못 잡는 것이다. 보고에 그대로 넘긴다.
- 자리표시(`[원장님 확인]`, `[추후 기입]`)는 warn으로 잡힌다. 정상이다.

### 5. GEO 점수
```bash
python3 $SKILL/scripts/geo_check.py output/<폴더>/<원고>.md
```
- 85점 이상이면 통과다. 자리표시와 감수 표기 말고 다른 미달 항목이 있으면 고친다.
- 분량(G23)은 공백 제외 2,500~4,000자다. 글자 수는 이 검사기로만 센다. `wc -m`은 C 로케일에서 바이트를 세서 약 3배로 부풀려진다.
- 점수를 올리려고 규정을 굽히지 않는다.

### 6. 시뮬레이션 검수 (글마다, 에이전트 2개를 동시에)
[references/simulations.md](references/simulations.md)의 지침을 그대로 써서 **독자 시뮬레이션**과 **심의 시뮬레이션** 에이전트를 한 번에 띄운다.
- 에이전트에는 **원고 경로만** 넘기고 내 판단은 넘기지 않는다. 내가 놓친 것을 찾게 하려는 것이다.
- 심의 에이전트는 인용 문헌 원문을 직접 열어 대조한다. 이 단계가 가장 많은 오류를 잡는다.
- 반영할 때 새 의학 사실은 출처 없이 쓰지 않는다. 출처가 없으면 빼거나 `[원장님 확인]`으로 돌린다.
- 반영 후 4·5단계를 다시 돌린다.

### 7. 이미지
[references/images.md](references/images.md)를 따른다. 요점은 다음과 같다.
- AI 이미지에는 글자를 넣지 않고, 라벨은 HTML로 얹어 PNG로 렌더한다.
- 의학적 위치(깊이·부위)는 AI에 맡기지 않는다.
- 실제 인물 사진풍, 시술 장면, 전후 비교는 금지한다.
- 사람은 수채화 일러스트로만 넣고, 바로 아래에 `*AI로 만든 일러스트이며 실제 환자가 아닙니다.*`를 붙인다.
- 생성 기록을 `images/raw/PROVENANCE.md`에 남긴다.

### 8. 네이버 게시 준비 (발행은 사람이)
```bash
python3 $SKILL/scripts/naver_export.py output/<폴더>/<원고>.md
```
`naver/`에 다음을 만든다. 발행 버튼은 누르지 않는다.
- `copy.html`: 스마트에디터에 붙여 넣을 본문. 사진 자리는 노란 상자로 표시된다.
- `preview.html`: 사진이 들어간 검토용 화면.
- `images/`: 올릴 순서대로 번호를 붙인 사진.
- `POSTING.md`: 제목, 태그, 사진 순서, 발행 전 확인 목록. 자리표시가 남아 있으면 맨 위에 "아직 발행하지 마세요"를 적는다.

미리보기는 휴대폰 폭(390px)으로 확인한다. 도식 글자는 이 폭에서도 읽혀야 하므로 라벨은 26px 이상으로 쓴다.

### 9. 기록과 보고
- 검수 기록을 `docs/reviews/<날짜>_<슬러그>.md`에 남긴다. 틀은 [assets/review-log-template.md](assets/review-log-template.md)다.
- 자리표시가 쌓이면 원장님 확인 질문지로 묶는다. 질문은 번호 선택지로 만들고, 질문마다 반영할 파일·줄을 적는다. 받아도 쓸 수 없는 내용(후기, 효과 보장, 할인, 약 상품명)을 질문지 첫머리에 알린다.
- 사용자 보고에는 다음을 담는다.
  - medad block·warn 수와 warn 판단
  - GEO 점수와 미달 항목
  - 분량
  - 시뮬레이션에서 고친 것
  - 남은 원장님 확인 항목
  - 사전심의 필요 여부

## 판단이 어려울 때

- **규정이 애매하면 보수적으로 쓴다.** 빼도 글이 성립하는 표현이면 뺀다. "거의 없어요" 대신 "드물게 보고됐어요"가 안전하다.
- **부정 문맥도 조심한다.** "통증이 없는 것은 아니에요"처럼 부정하는 말은 괜찮다. 하지만 "통증 걱정 없는"처럼 결과적으로 안전을 보장하는 말은 안 된다.
- **비교는 방식끼리만 한다.** "초음파는 점 형태, 고주파는 넓게"는 괜찮다. "더 효과적", "덜 아프다" 같은 우열 결론은 출처가 있어도 피한다.
- **병원이 정할 일을 내가 정하지 않는다.** 감수 표기 방식, "피부과" 명칭 사용(신고 진료과목), 사전심의 신청, 주소 공개 범위는 사용자 결정이다. 정해지면 `docs/decisions.md`에 기록한다.
- 이 스킬의 검사는 1차 거름망이다. 사전심의나 법률 검토를 대신하지 않는다고 보고에 밝힌다.

## 규칙 고치기

- 검사기가 놓친 표현이나 잘못 잡은 표현을 찾으면 `scripts/medad_rules.json`을 고친다.
- 그 문장은 `scripts/medad_cases.json`에 기대 결과(`B` block, `W` warn, `P` 통과)와 함께 추가한다.
- 그다음 회귀 시험을 돌려 전부 맞아야 한다. 규칙 형식은 [references/medical-ad-law.md](references/medical-ad-law.md) 끝에 있다.

```bash
python3 $SKILL/scripts/medad_selftest.py
```

병원 한 곳에만 해당하는 규칙(실명, 지점명)은 공통 규칙이 아니라 그 병원 폴더의 `medad_local.json`에 넣는다.
