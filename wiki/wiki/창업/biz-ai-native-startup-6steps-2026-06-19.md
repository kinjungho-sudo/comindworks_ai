# AI-네이티브 스타트업을 만드는 방법 — 6단계 운영 프레임워크

## 핵심 명제

> "AI가 반복 업무를 야간에 처리하는 동안 창업자는 제품 개선에 집중"

모두가 같은 LLM 모델을 쓰는 시대에 **진짜 경쟁 우위는 규율**이다.
매주 업무를 매핑하고, 컨텍스트를 쌓고, eval을 쓰고, 루프를 돌리는 **일관성**이 해자(moat)가 된다.

---

## 6단계 프로세스

### 1단계 — 업무 매핑 (Task Mapping)
반복되는 작업을 **자율성 레벨(L1~L4)**로 분류한다.

| 레벨 | 설명 |
|------|------|
| L1 | 사람이 전부 실행, AI 없음 |
| L2 | AI가 보조, 사람이 검토·승인 |
| L3 | AI가 실행, 사람이 예외 처리 |
| L4 | AI 완전 자율 실행 |

→ 지금 L1인 작업 중 L3~L4로 올릴 수 있는 것을 찾는 것이 출발점.

### 2단계 — 컨텍스트 시스템 구축
**Git 저장소 기반의 회사 운영 기억**을 만든다.

- 회사의 노하우, 프로세스, 결정 근거를 마크다운으로 버전 관리
- AI가 매번 같은 컨텍스트를 재학습하지 않아도 되는 구조
- LLM Wiki, CLAUDE.md 같은 방식이 이 단계의 실천 예시

### 3단계 — 단순한 자동화 선택
도구 선택 원칙: **필요 이상으로 복잡하게 만들지 않는다.**

| 상황 | 최적 도구 |
|------|-----------|
| 단순 반복 | 스크립트 |
| 판단 필요 | AI 보조 |
| 다단계 연결 | 워크플로 (n8n 등) |
| 자율 실행 | 에이전트 |

### 4단계 — 스킬과 eval 인코딩
반복 작업에 대한 **재사용 가능한 지침(스킬)**과 **품질 평가 기준(eval)**을 문서화한다.

- 스킬: "이 작업을 어떻게 해야 하는가" — 절차와 판단 기준
- eval: "잘 됐는지 어떻게 측정하는가" — 성공 지표

### 5단계 — 팀의 AI-네이티브 전환
모든 구성원이 **에이전트를 직접 활용하는 방식**을 체득한다.

- 특정 담당자만 AI를 쓰는 구조는 취약
- 팀 전체가 L3~L4 레벨로 작업을 올리는 습관 내재화

### 6단계 — 피드백 루프 운영
매주 시스템을 개선하고 시장에서 학습한다.

- 어떤 자동화가 잘 작동했는가?
- 어떤 eval이 틀렸는가?
- 다음 주 L1→L3으로 올릴 작업은 무엇인가?

## 코마인드웍스 적용 포인트

- **컨텍스트 시스템** = 이 LLM Wiki 자체가 2단계의 실천
- **스킬 인코딩** = wiki-collector, wiki-reader 등 스킬 파일
- **eval** = 수집 품질 검사, 분류 정확도 추적
- **피드백 루프** = 매주 index.md 현황 보고 + 개선
